# F1 繁中留言情感與主題分析

對自營 F1 粉專（FB／IG）留言做繁體中文情感分析與主題分類，產出車迷輿情分析報告：
各場比賽的情緒走向、各車手與車隊的討論熱度與正負評比例。

精實型專案，notebook 與報告為主，不部署服務。

## 隱私是這個專案的第一約束

**任何含他人留言的原始資料，永遠不進公開 repo。**
`.gitignore` 排除 `data/raw/`、`data/comments*`、`data/gold_set*`、`*_audit.json`。
repo 只放程式碼、匿名化樣本（≤ 50 則）、彙總統計結果。

原始需求只寫了移除用戶名稱、ID、連結。那不夠，真正的漏洞在**留言正文**：

| 類型 | 置換 | 說明 |
|---|---|---|
| 信箱 | `[信箱]` | 必須排在連結規則之前，否則會被當網域吃掉 |
| 連結 | `[連結]` | 含縮網址與裸網域 |
| @提及 | `[提及]` | 半形 `@` 與全形 `＠` |
| 電話與長數字 | `[號碼]` | 台灣手機、市話、8 碼以上連續數字 |
| 正文人名 | `[人名]` | 百家姓 + 1 到 2 字的啟發式 |

### 公眾人物必須保留

這是設計上最需要解釋的一點：**分析本身就是關於車手與車隊的討論**，
所以 Verstappen、紅牛必須留下，一般網友的名字必須移除。
因此採白名單（保留）加姓氏啟發式（移除）雙軌。

白名單在 `data/public_figures.json`。那是起始集，
**譯名沒有標準答案，需要人工複核與補齊**，檔案裡標了 `_todo`。

偏誤方向是刻意的：**寧可過度遮蔽也不要漏遮。**
每次遮蔽都記進 audit log，可事後複核有沒有誤刪車手名。
`NOT_NAMES` 是精確度的代價（「馬上」「高速」以姓氏字開頭但不是人名），
這份清單不完整就會誤遮，所以 audit log 必須留著。

## 指標為什麼逐類報

三分類的**中立類別是 macro-F1 的殺手**。正負好分、中立難分，
macro-F1 0.75 很可能是「正負各 0.85、中立 0.55」的平均。
只報 macro 會把這件事藏起來，而它正是報告裡最該討論的部分。

所以 `metrics.py` 的 `report()` 逐類報 P／R／F1／support，
並**指名最弱的類別**要求報告解釋原因。測試涵蓋兩種 macro 會藏起來的情況：
「正負漂亮但中立為零」與「accuracy 0.9 而 macro 低於 0.6」。

中立類不設硬門檻，但必須討論為什麼低。四種造成中立難分的情況
（反諷、混合對象、純資訊提問、無對象情緒）的判準寫在 codebook。

## 資料取得

官方「下載你的資訊」**不含他人在你貼文下的留言**，這一點已查證，
所以 Meta Graph API 是唯一路徑。粉專管理員本人在 Development mode 下
拿 Page Access Token 讀自家貼文留言做得到，但 token 短效要手動延長，
IG 還要 Business／Creator 帳號綁 FB 粉專。

這一到兩天花的是權限而不是 NLP，所以排程上與其他專案並行處理，
pipeline 假設資料會以 CSV／JSON 落地後才進來。
